# video-compress

把单个视频或整个目录（递归）压成 H.264 + AAC 的 MP4，输出到新目录；源文件不改，相对目录结构保留。

## 用法

`<skill-dir>` 是当前 SKILL.md 所在目录。依赖 `ffmpeg` / `ffprobe`（macOS：`brew install ffmpeg`）。

```bash
python3 "<skill-dir>/scripts/compress_video.py" <source> \
    [-o OUT] [--max-size SIZE | --crf N] [--max-height H] [--audio-bitrate 128k] [--preset slow] [--dry-run]
```

| 参数 | 说明 | 默认 |
|---|---|---|
| `source` | 视频文件，或递归扫描的目录 | 必填 |
| `-o, --output` | 输出目录，不能在源目录内 | `<source>-compressed` |
| `--max-size` | 每个文件的目标大小（如 `5MB`、`800K`），从 CRF 20 起每次 +2 直到放得下，最高 36 | — |
| `--crf` | 固定画质，越小越清晰、文件越大；与 `--max-size` 二选一 | 23 |
| `--max-height` | 高度上限，只缩小不放大 | 不缩放 |
| `--audio-bitrate` | AAC 码率 | `128k` |
| `--preset` | x264 速度档，越慢同画质越小 | `slow` |
| `--dry-run` | 只列出计划，不编码 | — |

## 执行步骤

1. **定目标**：用户给了大小上限，或提到用途（发到哪里、给谁看）时，先查 [场景规则](references/scenarios.md) 取参数；用途和上限都不明确就用 `--crf 23`。完成标准：参数能说出来源（用户给的上限、场景规则，或默认画质）。
2. **看计划**：先 `--dry-run`，确认文件清单和输出路径，输出不在源目录里。
3. **压缩**：正式运行。脚本逐个编码并用 ffprobe 核对：有视频流、原有音轨没丢、时长偏差不超过 0.5 秒；按目标大小时还要求不超过上限。
4. **汇报**：完成标准是每个文件都有结果行。逐个报告大小变化、比例和所用 CRF；`FAIL` 的文件原样列出原因，不把部分成功说成全部完成。

## 取舍

- **目标大小下 CRF 升到 30 以上**，画面开始出现明显糊块和色带。宁可加 `--max-height` 降一档分辨率（1080 → 720），也不要只靠提高 CRF 硬压；脚本到 CRF 36 仍超标时会直接失败并给出这个提示。
- **已经低于目标的 MP4 原样复制**，不重复编码，避免二次压缩损失；其他容器（MOV、MKV 等）即使够小也会转码成 MP4。
- **画面以文字和纯色为主**（录屏、动画、演示）的视频很耐压，CRF 28–32 通常看不出损失；**实拍、运动多、噪点多**的视频对 CRF 敏感，优先降分辨率。
- **输出固定为 H.264 + AAC + faststart**：兼容性最好，网页可以边下边播。需要更小体积时 H.265/AV1 能再省 30–50%，但部分浏览器和平台不支持，这个脚本不做。
