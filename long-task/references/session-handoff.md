# 会话更换交接

用于用户已要求更换执行会话或跨宿主接手当前任务的情况。更换会话保留原任务范围与授权，不能用换模型、清空历史或重试来绕过审批、权限或安全限制；新执行先核对阻塞原因，只接续允许的工作。

## 交出旧执行

1. 复用最新交接与 [checkpoint](checkpoint.md)，记录角色/实例、当前请求及交接版本、仓库/分支/HEAD、未提交改动归属、已完成证据、待回报和下一步。不复制整段历史或初始化等待指令。
2. 按用户已指定的停止范围中断旧执行，用宿主支持的只读状态核对该会话的命令、子任务及后台写入者是否仍在运行。输入空闲、对话回退或进程退出都不能单独证明后台任务已停；状态不明时让新执行保持只读，明确报告缺口。
3. 区分“停止执行”“回退对话”“恢复代码”。先查当前宿主文档与可见选项；保留实现的接手只选择对话恢复，不恢复工作区。回退对话不撤销已执行的命令、外部操作或后台任务。没有回退能力时保存交接后退出，不用代码回滚模拟。
4. 在现有任务记录标记旧实例已停、仍运行或未知，以及取消/被替代的请求和未完成外部操作。后续旧实例回报只作历史证据，不自动推进新实例；对外通知仅沿用已有通信授权。

## 接入新执行

- 先读最新有效交接、裁决与验证，再核对真实仓库、worktree、分支、HEAD、staged/unstaged 和相关 untracked 改动。发现他方变化时停受影响写入，保留差异并交责任人确认；不搬走或回退共享改动。
- 明确新实例角色、可写范围和当前有效请求。既有编组沿用其唯一 writer、请求关联和消息序号规则，不从旧初始化文本重置状态；无编组时不新增角色协议。
- 逐项接续通过、阻塞、未执行与待回报状态。继承证据注明来源和基线，只补版本或契约变化影响的部分；外部操作结果未知时先读回，避免重复执行。
- 旧执行已确认不再写入、实时状态与交接一致、职责和下一条授权动作明确后才恢复修改。否则完成可独立的只读核验并报告缺口，不把新会话已打开当作接手完成。
