## 进度文件模板

复制到 `<任务工作目录>/<task-slug>.md`：

```markdown
# 任务：<标题>

- 状态：进行中 | 等待外部结果 | 需要用户输入 | 已完成
- 创建：<YYYY-MM-DD>
- 更新：<YYYY-MM-DD>

## 目标与验收
<一句话目标 + 怎样算完成>

## 恢复锚点
- 仓库 / 工作目录：<本地精确路径；分享前脱敏>
- 分支 / 完整 HEAD SHA：<逐仓记录；非 Git 任务写不适用>
- 未提交改动：<本任务涉及的文件和无关改动边界>
- 已有证据：<检查结果、对应 SHA 或环境、报告路径>

## 阶段
- [x] 1. <已完成的阶段>
- [ ] 2. <当前阶段>  ← 进行中
- [ ] 3. <后续阶段>

## 当前进度
- 正在做：<具体在干什么>
- 下一步：<一条可执行的命令或操作，含预期结果>
- 等待对象：<若有，记录 job/task ID、最后检查时间和状态>
- 继续 / 停止条件：<什么变化值得继续，什么情况需要用户输入>
- 授权边界：<已获授权的下一步；尚需授权的具体动作>

## 关键决策 / 结论
- <决定了什么、为什么这么定>

## 相关文件
- `path/to/file` — <作用 / 改了什么>

## 待办 / 坑
- <还没解决的、要小心的>
```

进度文件要**简洁**——只记“恢复任务所需的最小信息”，别把它自己也写爆。需要本地保存时使用任务工作目录或当前宿主的本地忽略方式，不自动修改仓库 `.gitignore`。
