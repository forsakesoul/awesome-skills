# Daily Report Skill

基于 Git 提交记录生成工作日报，可选地把每个分支关联的 GitLab Work Item 按阶段（需求梳理 / 技术设计 / 开发中 / 测试中 / 验收中 / 待上线 / 已上线 / 已合入主干）标出来。

`<skill-dir>` 是当前已加载 SKILL.md 的父目录，配置 `config.json` 也在该目录，不依赖调用时 cwd。`<skill-dir>/private.md` 存在时先读，它记录只对本机成立的归档布局和宿主限制。

## 按模式读取

- 缺少配置或要调整来源 / 输出：读 [配置说明](references/configuration.md)。
- 日报：读 [日报流程与模板](references/daily.md)。**每次产出两份**（人读版 + 明细版）。
- 周报 / 周功能总结：读 [周报流程与模板](references/weekly.md)。素材优先取本周日报，逐日读、按分支归并，**一条分支一节**；本周缺日报的日子先补日报，不重新采集、不逐笔翻代码。
- 一页纸小结（用户说"简短总结下""汇报用的版本""做成表格"）：读 weekly.md 的《周报·一页纸小结》。三列表格（重点工作｜关键进展｜风险及应对措施）；已上线的只写上线日 `M-D`，未上线的写实际进度；不写笔数、分支名、MR 号；范围按 `config.report_scope`。
- 公司 / 个人工作周报（用户说"按公司模板出一份"）：读 weekly.md 的《公司 / 个人工作周报（固定模板口径）》。从同期个人周报投影，另出一份，只落本地文件。
- 用户只要口头总结时直接回复；有明确文件输出要求才写到指定位置。GitLab Work Item 默认只做来源关联，写 tracker 需独立授权。

## 日报双版本

- **人读版**（缺省 `MMDD.md`）：一屏说清"做了什么、到哪一步、要你处理什么"。只写事 + 进度，不写 commit hash、笔数、分支名、ahead-behind、MR 与工单编号（"需要处理"区例外，那是行动项，要能定位）。
- **明细版**（缺省 `MMDD.agent.md`）：全量事实档案。**周报的素材源是它。**

顺序固定先明细、后投影人读；两份共用同一份事实，条数不要求对应。历史归档若只有明细版且占用主文件名，读取时 `MMDD.agent.md` 优先、缺失回退 `MMDD.md`，不要因找不到人读版而重采或报错。

## 待办台账（跨日累积）

日报的"需要处理"是一份跨日台账在当天的投影，不是每天重写的段落。台账在 `config.todo_ledger.dir`（本地文件，不入库），按月一个文件 `{YYYY}-{MM}.md`。三条不变量：

- **编号 `T-xx` 不可变、不回收、跨月连续**，按文件末尾的编号水位取号。
- **票号与 MR 号写成可点链接** `[短名#编号](真实地址)`，ID 必须实测，不凭上下文猜。
- **日报只输出三类**：当天新增、当天有变化、标了"阻塞"且未完成的；其余一行汇总"另有 N 项历史待办未动"。

字段、状态、换月结转与首次建立见 daily.md 的《待办台账（跨日累积）》。

## 使用方式

触发词：日报类"生成日报""今日日报""更新下今天的日报"；周报类"生成周报""周功能总结""上周做了什么"。可指定日期（"生成 6 月 15 日的日报"）和仓库路径。

生成前先冻结目标日期和时区，然后用随 Skill 提供的脚本采集：

```bash
python3 "<skill-dir>/scripts/collect_commits.py" <repo...> --date YYYY-MM-DD -a <name> -a <email>
```

两条最容易出错的口径，细节与其余归属规则见 [归属、去重与 Work Item 规则](references/attribution.md)：

- **日期一律按北京时间**：脚本默认 `Asia/Shanghai`，不随本机时区；手写 `git log` 必须带 `+08:00` 偏移，不用本机 `date` 判断"今天"。
- **多个作者写成多次 `-a`**，不写 `a|b`（Apple Git 按 BRE 解析会静默返回 0 条）。采集结果为 0 时先怀疑这条。

写报告时按 attribution.md 逐条对照：author date 归属、半开区间、跨分支与同远端去重、章节按分支、票据按提交、Work Item 跨项目解析。落盘后回读校验每个 hash 都在文件内、各节条目数与声明笔数一致。

## 保持 config.json 同步

`config.json` 是本地真实配置，在 `.gitignore` 内；真实仓库路径、分支名、Work Item 标题只写在这里，受版本控制的文件只写泛化示例。**每次生成日报后回填**，让它反映当前实际环境：仓库路径、集成分支与同远端目录组、新出现的 Work Item 归属（ID 与标题必须来自实际查询或提交正文）。回填字段与优先级见 configuration.md 的《每次生成后回填》，回填后校验 JSON 合法。

## 采集完成条件

记录实际成功 / 失败 / 跳过的仓库与精确日期区间。采集器非零或 incomplete 表示覆盖不全，合计只代表成功仓库；可产出明确标注缺口的部分报告，不能写成完整日报或零工作。零提交、未提交改动、QA / 设计 / 沟通分别取证。
